# 全球互联网扫描系统 —— 开发方案

> 版本：v1.0 ｜ 日期：2026-08-28 ｜ 状态：已评审定稿
> 项目代号：**NetAtlas**（互联网扫描与资产测绘平台）

---

## 0. 项目目标与合规前提

构建一套可在单台 Windows 主机上运行的、面向学术研究的互联网测绘平台：

1. **L3/L4 发现层**：无状态扫描遍历 IPv4 地址空间（两阶段：存活探测 → 全端口）；IPv6 采用 TGA（目标生成算法）+ Hitlist 种子驱动的智能扫描。
2. **L7 采集层**：对存活主机做应用层协议握手，抓取 banner、TLS 证书、HTTP 指纹等。
3. **主机富化层**：BGP/AS 路径、地理定位、网络时延、正反向 DNS。
4. **分类分析层**：并行地对 Web 站点进行多级分类（精确到最小子类，保留分类层级路径），重点识别文件存储/数据分发类站点（如 ESA Gaia CDN），单独成库。
5. **存储层**：借鉴 Censys 的 CQRS + 列式存储思想，本地落盘为 zstd 压缩 NDJSON（原始层）+ Parquet（列式层）+ DuckDB（查询目录层），空间效率最优。
6. **管控层（WebUI）**：全局带宽调节、模块级启停、实时数据展示、各存储层本地路径标注；启动前自动探测空闲端口。

**合规红线（硬约束，写入运行时）**：
- 排除列表（IANA 保留段、RFC1918、组播、opt-out 列表）强制加载，扫描器启动前校验；
- 所有探测包携带可识别的研究标识（HTTP User-Agent / probe 元数据含项目联系邮箱）；
- 默认上行限速（用户约束 25 Mbps），支持 WebUI 动态下调，严禁上调超过物理带宽；
- 提供 `docs/RESPONSIBLE_SCANNING.md`，维护 `config/exclude.txt` 与 opt-out 机制。

## 1. 调研结论摘要

### 1.1 IPv4 无状态扫描（L3/L4）

| 维度 | 结论 |
|---|---|
| 选型 | **masscan**（C 实现，原生支持 Windows + Npcap，10M pps 级，自带独立 TCP/IP 栈）为主力；ZMap 仅支持 Linux/裸机 netmap，Windows 不可用，作为 Linux 部署可选后端 |
| 两阶段法 | 阶段一：常用端口集（top ~200 端口）全网发现 → 输出存活 `ip:port` 流；阶段二：对存活主机/段做全 65535 端口细扫 |
| 速率换算 | 25 Mbps ≈ 3.125 MB/s；TCP SYN 包（含以太网/IP/TCP 头）约 64-74 B/pkt → 理论上限 ~42k pps；工程取值 **默认 8,000 pps**（留 L7 抓取余量），masscan `--rate` 动态下发 |
| 关键配置 | `--excludefile` 强制排除；`--banners` 关闭（banner 交 L7 层做，避免 masscan 自有栈与系统栈 RST 冲突）；`--source-port` 固定 + Windows 下无需防火墙规则（Windows 不回 RST，Linux 需 iptables DROP） |
| 随机化 | masscan 内置 BlackRock 随机化目标顺序，避免热点网段冲击 |
| 参考实践 | Rapid7 Sonar：500k pps/机上限、分布式多源 IP、与 ISP 协调；Censys：100 常用端口常规扫 + 300 云端口高频扫 + 9 个月周期全端口扫 + ML 预测式扫描 |

### 1.2 IPv6 扫描（TGA/PAS）

IPv6 空间 2^128，穷举不可行（万兆链路需上亿年），学界主流为**种子驱动的目标生成算法（TGA）**：

| 算法 | 原理 | 开源/语言 | 本项目采用 |
|---|---|---|---|
| 6Gen | 凝聚层次聚类(AHC)，高密度区域贪婪扩展 | 否(C++)，O(n³) | 不采用（太慢） |
| **6Tree** | 分裂式层次聚类(DHC)构建空间树，按节点活跃密度生成目标，多轮反馈 | 是(C++)，O(nlogn) | **核心采用（Python 重实现）** |
| **Entropy/IP** | 相邻半字节按经验熵分段，贝叶斯网络建模段间依赖，统计采样生成 | 是(Python) | **辅助采用** |
| 6Hit | DHC + 强化学习分配探测预算 | 是(Python) | 反馈机制借鉴 |
| 6Scan / 6Forest / 6GAN / 6VecLM | 区域编码加速 / 孤立森林去噪 / GAN / 语言模型 | 部分开源 | 二期可选 |
| **PAS（别名前缀处理）** | /96 随机 3 探针全响应即判别名前缀；多层次伪随机探测改进 | — | **采用（主动别名检测）** |

**种子来源（hitlist）**：IPv6 Hitlist Service（ipv6hitlist.github.io，Gasser 等，数千万响应地址 + 别名前缀标注）、CAIDA Ark、Rapid7 FDNS、Cisco Umbrella / Tranco 域名 AAAA 解析。

**扫描器**：IPv6 无状态探测用 masscan（支持 IPv6）/ 自研 Scapy 探测协程；别名前缀列表参与目标过滤。

### 1.3 L7 应用层扫描

| 维度 | 结论 |
|---|---|
| 选型 | **ZGrab2**（Go，模块化插件架构，33+ 协议：HTTP/TLS/SSH/FTP/SMTP/MySQL/Redis/SMB/Modbus/BACnet/DNP3/S7…，Censys 生产级验证）作为外部进程；**Python 异步抓取器**作为内置兜底（无 Go 工具链时仍可用 HTTP/TLS/DNS 核心协议） |
| 数据流 | masscan 输出 `ip:port` → 流式管道 → ZGrab2（CSV stdin：ip,domain,tag,port）→ NDJSON 输出 → 存储层 |
| 架构借鉴 | Scanner 接口（Init/Scan）+ 模块注册表 + DialerGroup 连接管理 + TimeoutConnection（读限量防恶意大响应）；完整握手 transcript 落盘，分析后置 |
| Windows | ZGrab2 提供 Windows 可执行文件交叉编译（`GOOS=windows`），项目内 `bin/` 目录存放 |

### 1.4 存储架构（对标 Censys/Shodan）

| 层 | Censys 做法 | 本项目（单机 Windows） |
|---|---|---|
| 原始层 | Avro 快照 | **zstd 压缩 NDJSON**（按日期+端口分片，~10:1 压缩） |
| 实体/列式层 | Bigtable 增量编码（delta encoding，~500TB/年） | **Apache Parquet**（Snappy/Zstd，按 `date/port` 分区，字典+游程编码，空间效率最高） |
| 查询层 | BigQuery + Elasticsearch | **DuckDB**（进程内列式 OLAP，直接查 Parquet，零服务开销） |
| 元数据/状态 | — | **SQLite**（任务状态、opt-out、分类结果索引、WebUI 状态） |
| 关键取舍 | CQRS 读写分离 | 写入侧最小处理（落盘优先），富化/分类异步并行消费；定期 compact 小分片 |

**为何不用 Scala/Spark**：单机 25 Mbps 带宽下数据规模（每日 GB 级）远未到分布式门槛；DuckDB+pandas/pyarrow 在 Python 内即可完成统计，减少 JVM 开销与运维复杂度。后续数据量上量后可平移至 Spark（Parquet 格式天然兼容）。

### 1.5 网站分类标准

采用 **IAB Tech Lab Content Taxonomy 3.0**（业界广告/内容分类标准，4 级层级）为主干，叠加测绘领域自定义扩展类目：

- `Technology & Computing / Internet / File Sharing & Storage`（重点：文件存储、CDN、数据分发镜像站，如 ESA Gaia CDN 这类科研数据分发节点 → `T&C/Internet/Data Distribution Mirror`）
- `Science / Astronomy & Space`（学术数据集）
- 自定义：`Infrastructure/CDN`、`Infrastructure/IoT & ICS Device`、`Infrastructure/Default & Error Page` 等测绘特有类目。

分类信号：域名关键词、HTTP Server/X-Powered-By 头、HTML title/body 特征（Wappalyzer 规则集思想）、TLS 证书 SAN、路径指纹（`/pub/`、`/ftp/`、`Directory listing`）、MIME 类型分布。分类结果含**完整层级路径**（如 `Technology & Computing > Internet > Data Distribution`），写入独立分类库 `classification.parquet` + SQLite 索引。

## 2. 总体架构

```
┌─────────────────────────── NetAtlas Orchestrator (Python 3.13) ───────────────────────────┐
│                                                                                            │
│  ┌──────────┐   ip:port 流   ┌───────────┐  NDJSON   ┌──────────────┐   ┌───────────────┐ │
│  │ L4 发现层 │ ────────────▶ │ L7 采集层 │ ────────▶ │ 存储管线      │   │ 分类/富化引擎  │ │
│  │ masscan  │               │ ZGrab2    │           │ NDJSON.zst → │◀─ │ (并行消费者)   │ │
│  │ (C,外部) │               │ Go / Py   │           │ Parquet 分区  │   │ 分类/Geo/ASN/ │ │
│  └──────────┘               └───────────┘           │ DuckDB目录   │   │ DNS/RTT       │ │
│        ▲                      ▲                     └──────────────┘   └───────────────┘ │
│  ┌──────────┐   ┌───────────┐        ▲                                │                  │
│  │ IPv6 TGA │   │ 种子管理   │        │ 统一令牌桶带宽控制器 (25Mbps)    │                  │
│  │ 6Tree+EIP│   │ Hitlist   │        └────────────────────────────────┘                  │
│  └──────────┘   └───────────┘                                                            │
│                                                                                            │
│  ┌────────────────────────────────────────────────────────────────────────────────────┐  │
│  │ WebUI 管控面 (FastAPI + 原生前端)：实时状态 / 带宽滑块 / 模块启停 / 存储路径标注      │  │
│  └────────────────────────────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────────────────────────┘
```

**数据流（流水线、全程流式不落地内存）**：
`目标生成(IPv4 CIDR 迭代 / IPv6 TGA) → L4 SYN 探测 → 存活队列 → L7 协议握手 → 原始落盘(NDJSON.zst) → [富化+分类消费者] → Parquet 分区 → DuckDB 视图 → WebUI 展示`

## 3. 语言与工具选型（决策记录）

| 模块 | 语言 | 理由 |
|---|---|---|
| L4 无状态扫描 | **C（masscan 外部进程）** | 发包/抓包栈必须内核旁路级性能，C 是唯一现实选择；Windows 原生支持 |
| IPv6 TGA 目标生成 | **Python**（NumPy 向量化） | 6Tree/EntropyIP 官方实现即 Python；生成是离线批处理，性能足够 |
| L7 协议握手 | **Go（ZGrab2 外部进程）** + Python asyncio 兜底 | 高并发有状态连接、证书解析生态成熟；编译为单 exe 便于 Windows 部署 |
| 调度/编排/带宽控制 | **Python 3.13（asyncio + 子进程管理）** | 胶水层，生态最全 |
| 数据处理/统计 | **Python（DuckDB + pyarrow + pandas）** | 单机规模下替代 Scala/Spark（见 §1.4） |
| WebUI 后端 | **Python（FastAPI + uvicorn）** | 与编排层同进程，REST + WebSocket 推送 |
| WebUI 前端 | **原生 HTML/JS/CSS（无构建链）** | Windows 开箱即用，无 node 依赖 |
| 可选 C++ 扩展 | C++（6Tree 原生、高吞吐解析器） | 二期性能优化预留接口 |

## 4. 模块设计要点

### 4.1 L4 扫描模块（`modules/l4_scanner.py`）
- 封装 masscan 子进程：`masscan <ranges> -p<ports> --rate <pps> --excludefile config/exclude.txt -oJ -`（JSON 流输出）
- 两阶段调度：阶段1 top-ports 发现 → 阶段2 存活网段全端口（由调度器按优先级队列下发）
- 支持运行时改速率（向 masscan 管理通道/重启续扫，masscan 支持 `--resume paused.conf`）
- IPv6 模式：`masscan --ipv6` 或内置 Scapy ICMPv6/TCP 探针

### 4.2 IPv6 TGA 模块（`modules/ipv6_tga.py`）
- **6Tree（Python 重实现）**：种子 → 32 维半字节向量 → 自顶向下按"最活跃维度"分裂空间树 → 节点密度 > 阈值则细分 → 叶节点按密度配额采样生成目标（`*` 通配半字节）
- **Entropy/IP 模式**：按熵分段 + 段值联合分布采样
- **别名前缀检测（PAS）**：候选 /96 前缀随机 3 探针，全响应 → 标记别名前缀，加入过滤集
- **反馈循环**：每轮探测命中率反馈 → 调整子空间下一轮预算（借鉴 6Hit ε-greedy）
- 种子导入：hitlist 下载器 + 本地缓存

### 4.3 L7 抓取模块（`modules/l7_grabber.py`）
- 主路径：ZGrab2 子进程，`echo "ip,domain,http,80" | zgrab2 multiple -c multi.ini`
- 兜底路径：Python asyncio 抓取器（HTTP HEAD/GET、TLS 证书链提取、banner 读取），内置并发信号量 + 每连接读上限（1 MB）
- 输出统一 NDJSON schema：`{ip, port, protocol, timestamp, banner, tls:{chain...}, http:{status,headers,title}, rtt_ms, error}`

### 4.4 富化模块（`modules/enrich.py`）
- 地理/ASN：MaxMind GeoLite2-City/ASN（`geoip2`，许可需用户自行下载放置 `data/geoip/`）；无库时降级为 RIR 统计
- BGP 路由/AS 路径：pyasn（离线 RIB 快照）+ 可选 BGPStream
- 时延：TCP connect RTT（L7 握手顺带记录）
- DNS：正/反向解析，aiodns 批量协程；域名系统扫描（子域枚举二期）

### 4.5 分类引擎（`modules/classifier.py`）
- 规则引擎（Wappalyzer 风格 JSON 规则：`classification/rules/*.json`）+ 关键词/正则信号评分
- 输出：`{host, category_path: ["Technology & Computing","Internet","Data Distribution"], confidence, signals}`
- 文件存储/数据分发站点（FTP 列表、Apache autoindex、CDN 头特征）高优先级规则，单独写 `site_classification` 库

### 4.6 带宽控制器（`orchestrator/bandwidth.py`）
- 全局令牌桶：容量 = 用户上行（默认 25 Mbps），WebUI 可调 1–100%
- 各模块上报速率，控制器按比例分配 quota（L4 发包优先，L7/DNS 次之）
- 观测：滑动窗口吞吐统计 → WebUI 实时曲线

### 4.7 存储管线（`storage/`）
- `writer.py`：NDJSON 分片滚动写入（按 256MB/小时滚动）+ zstd 压缩 → `data/raw/yyyy-mm-dd/protocol/`
- `compactor.py`：定时任务将小分片合并转 Parquet（pyarrow，zstd level 6，行组 128MB）→ `data/parquet/table=hosts/date=.../`
- `catalog.py`：DuckDB 注册 Parquet 视图 + SQLite 元数据库（`data/meta/netatlas.db`）
- 保留策略可配（原始层默认 30 天，Parquet 长期）

### 4.8 WebUI（`webui/`）
- FastAPI：`/api/status`（模块状态/速率/计数）、`/api/bandwidth`（GET/POST）、`/api/modules/{name}/start|stop`、`/api/storage`（各层路径+大小）、`/api/query`（DuckDB 只读查询代理）、WebSocket `/ws` 实时推送
- 前端单页：仪表盘（吞吐曲线、发现计数、分类 TOP）、模块控制面板、存储路径面板、全局带宽滑块、日志 tail
- 启动时从 8000–9000 探测空闲端口并打印访问地址

## 5. 带宽预算（25 Mbps 约束下的分配策略）

| 消费者 | 默认配额 | 说明 |
|---|---|---|
| L4 masscan 发包 | 12 Mbps（~18k pps SYN） | 主吞吐，全网 IPv4 top-ports 约 2 天级 |
| L7 握手回传 | 8 Mbps | 命中流决定，自适应 |
| DNS/富化 | 2 Mbps | 批量解析 |
| 预留/重传 | 3 Mbps | 丢包重试、管理面 |
| **合计** | **25 Mbps** | 控制器动态再平衡，物理带宽波动时自动收缩 |

> 注：全端口（65535）IPv4 穷扫在 25 Mbps 下需约 1.5 年，方案采用"top 端口全覆盖 + 存活主机全端口 + 历史端口热度加权"的 Censys 式分层策略，保证学术价值密度。

## 7. 风险与对策

1. **合规/滥用投诉** → 强制排除列表、opt-out、研究标识、速率保守默认值；
2. **Windows 下 masscan 依赖 Npcap** → 启动脚本检测并给出安装引导；
3. **磁盘膨胀** → Web 正文抓取限量（默认仅首 64KB + title/headers），原始层滚动保留；
4. **25 Mbps 下 IPv6 命中率低** → TGA + hitlist 种子优先，别名前缀过滤，预算反馈；
5. **单机可靠性** → 断点续扫（masscan resume + SQLite 游标）、模块看门狗自动重启。
